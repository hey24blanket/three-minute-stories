# 삼분극장

한 편에 3분. 일곱 평론가의 감상평을 거쳐 두 번 개고하는 이야기 게시판입니다. 편집부 글은 게시판에 공개하고, 직접 작성한 작업실 원고와 댓글·별점은 비공개 Blob에 저장합니다.

## 편집부 예약 실행

- 운영 게시판 `GET https://three-minute-stories.vercel.app/api/board`에서 공개 글의 `next`와 일곱 평론가 설정을 읽습니다.
- 공개 이야기마다 `editorial/<id>.json` 파일 하나를 사용합니다. 첫 이야기 파일이 형식의 예입니다. 공개 응답에서 계산된 `editorial`, `next` 필드는 JSON에 저장하지 않습니다.
- 정기 신규 글은 서울 날짜와 시간을 넣은 `<YYYY-MM-DD>-09` 또는 `<YYYY-MM-DD>-18` ID로 생성합니다. 같은 파일이 이미 있으면 재등록하지 않습니다. 초안을 올릴 때 `createdAt`, `cycleAt`, `stepAt`을 현재 UTC ISO 시각으로 설정하고 `step: 0`, `versions: [{number: 1, body, notes: "", comments: []}]`를 사용합니다.
- 처음 작성할 때는 시간 코드가 있는 3분 분량의 완결된 영상용 원고를 올립니다. 각 이야기에 고유한 제목과 장르를 붙입니다.
- 평소에는 `Date.now() >= Date.parse(stepAt) + 3600000`일 때 한 단계씩 진행합니다. 1단계는 Ver.1 감상평, 2단계는 Ver.2, 3단계는 Ver.2 감상평, 4단계는 Ver.3입니다. 한시적인 편집부 가속 중에는 운영 API의 `next.dueAt`과 `next.intervalMinutes`를 확인하고, 종료 시각 뒤에는 원래 60분 기준을 적용합니다. 성공한 단계의 저장 직전 현재 UTC ISO 시간을 `stepAt`에 적습니다.
- 감상평 단계에서는 최신 버전에 일곱 평론가의 댓글을 추가합니다. 각 댓글은 `{id:"reader-"+readerId,reader:readerId,body,visual,stars:0,at}`입니다. `body`는 번호가 붙은 네 줄, 200자 안팎으로 씁니다. `visual`에는 번호를 제외한 세 줄을 배열로 넣습니다. Ver.1에서는 이미지 방향을 제안하고 Ver.2에서는 실제 삽화를 평가합니다. 개고 단계에서는 `{number,body,notes,comments:[],at}`를 추가하고, 이미 게시된 버전은 보존합니다. `notes`에는 실제 반영한 의견과 장면을 적습니다.
- 변경 직전에 파일을 다시 읽고 GitHub blob SHA를 사용해 갱신합니다. 실패하면 새 상태를 확인합니다. 댓글 ID와 버전 번호로 중복을 피하고 Vercel 운영 반영을 확인합니다.
- 별점과 직접 쓴 의견은 공개 JSON에 복사하지 않습니다. 예약 개고에서는 연결된 작업실의 해당 버전 의견과 별점만 읽어 별점이 높은 순으로 반영합니다.

## Ver.2 삽화 게시

1. Ver.1의 일곱 이미지 의견과 별점이 높은 피드백을 검토해 Ver.2 원고를 마무리합니다. 최근 삽화가 있는 다섯 작품의 매체·팔레트·구도를 살피고, 바로 앞 작품과 다른 매체를 우선합니다. 같은 작품의 인물과 모든 씬에는 정한 스타일과 캐릭터 기준을 적용합니다.
2. 이미지 생성 도구로 개별 등장인물 이미지와 각 씬의 대표 이미지를 두 장씩 만듭니다. 한 장에는 공간이나 상황을, 다른 한 장에는 같은 씬의 인물 행동이나 정서가 드러나는 순간을 담습니다. 인물 외형·의상·비율이 이어지는지, 씬의 시간·구도·행동이 본문에 맞는지 확인합니다. 각 파일에 한국어 대체 텍스트를 작성합니다.
3. 원고는 `[00:00–00:20 · 씬 제목]` 형식의 독립된 시간표시 줄을 사용합니다. Ver.2 객체에 아래 형식의 `illustrations`를 넣습니다. 모든 인물과 모든 씬 항목이 채워져야 합니다. 같은 씬 번호를 가진 두 이미지를 원하는 표시 순서대로 넣습니다. 화면에는 인물 이미지가 먼저 나오고, 씬 이미지는 해당 씬 제목 아래에 나옵니다.

```json
{
  "style": {"medium":"리소그래프","palette":"청록과 주홍","composition":"사선 원근과 넓은 여백"},
  "characters": [
    {"name":"등장인물 이름","src":"/illustrations/story-id/v2/character-01.webp","alt":"인물의 외형과 옷차림"}
  ],
  "scenes": [
    {"scene":1,"src":"/illustrations/story-id/v2/scene-01-a.webp","alt":"첫 씬의 공간과 인물 위치"},
    {"scene":1,"src":"/illustrations/story-id/v2/scene-01-b.webp","alt":"첫 씬에서 인물이 행동하는 순간"}
  ]
}
```

4. 실제 생성 이미지를 웹용으로 변환해 `public/illustrations/<story-id>/v2/`에 둡니다. `node scripts/check-illustrated-version.mjs editorial/<story-id>.json --require-two`로 파일 포맷과 씬별 누락을 확인합니다. GitHub에 바이너리를 보낼 때는 base64 blob으로 업로드합니다. 도구 출력 한도가 작으면 파일을 3의 배수 바이트 단위로 나눠 각 조각의 base64를 이어 붙입니다.
5. 최신 main의 트리를 바탕으로 Ver.2 JSON과 실제 이미지 파일을 같은 커밋에 넣고, main이 앞선 SHA에서 바뀌지 않았을 때만 반영합니다. 생성 도구나 파일 전달이 막히면 문제를 알리고 Ver.2를 공개 대기로 남깁니다. 배포된 이야기와 모든 삽화 URL을 확인한 뒤에 다음 단계로 넘어갑니다.

## Ver.3 최종 원고·삽화 게시

1. Ver.2의 원고와 실제 삽화에 대한 일곱 평론가의 의견과 작업실 피드백을 검토해 3분짜리 최종 원고를 완성합니다. 원고가 확정되면 컷의 순서, 인물의 동선과 외형, 빛과 색, 주요 소품이 장면 사이에 이어지는지 확인합니다.
2. 시간표시가 있는 최종 원고의 각 씬에 서로 다른 컷을 두 장에서 네 장까지 둡니다. 공간과 인물의 관계를 보여 주는 컷과 핵심 행동·표정·소품을 보여 주는 컷을 기본으로 하고, 이야기의 전환을 보여 줄 필요가 있는 씬에만 컷을 더합니다. 최종 원고에 맞는 Ver.2 삽화와 인물 이미지는 확인 후 재사용할 수 있습니다. 바뀐 연출이나 빠진 순간은 이미지 생성 도구로 새로 만들고 열어서 점검합니다.
3. Ver.3 객체에 같은 `illustrations` 구조를 저장합니다. 씬 번호는 Ver.3 원고의 순서로 매기고 같은 씬의 이미지를 화면에 보여 줄 순서대로 넣습니다. 새 파일은 `public/illustrations/<story-id>/v3/`에 두고, 재사용하는 이미지에는 같은 작품의 기존 `v2/` 경로를 적습니다. 모든 컷에는 개별 경로와 한국어 대체 텍스트가 필요합니다.
4. `node scripts/check-illustrated-version.mjs editorial/<story-id>.json --version=3`으로 검사합니다. 최신 main을 기준으로 최종 JSON과 새 이미지 파일을 한 커밋에 등록하고, 앞 버전과 감상평을 보존합니다. 필요한 컷이 준비되지 않으면 4단계는 재시도로 남깁니다. 운영 게시판에서 최종 원고와 모든 삽화가 씬별로 제공되는지 확인합니다.

## 작업실 연결

다른 기기에서 같은 작업실을 쓰려면 본인만 아는 연결 키로 로그인합니다. 편집 연동 ID는 작업실 연결 키의 SHA-256 지문입니다. 사이트에서 복사한 ID를 `editor:` 접두사 없이 `EDITOR_WORKSPACE_ID`에 넣으면 예약 개고가 해당 작업실의 공개 편집부 글에 달린 의견을 읽을 수 있습니다. 환경 변수는 `editor-feedback` 브랜치 Preview에만 적용하고 이 브랜치를 재배포합니다.

`/api/editor-feedback`는 Vercel Authentication으로 보호된 해당 Preview에서만 제공됩니다. 운영 주소에서는 이 경로가 404를 반환합니다. 작업실 키, 직접 작성한 개인 원고, 다른 작업실의 데이터는 이 경로에 포함하지 않습니다.
